## 分流闭环（sec-01 叠加能力）

- **策略页**：当日必须选定唯一规矩——`merge`（同指纹收成一单）或 `chain`（分单再串联），选定即写进生效说明，当天不许换；处置单未收口时生效说明禁止改动。
- **候审区（标题固定「待认领」）**：未认领告警集中展示；认领动作必须带操作员名。两人抢同一条只成一笔，另一笔落库为「争抢失败」并在台面与详情露出。级别空缺的告警既不许进合并、也不许被认领。
- **处置单**：`merge` 下同指纹告警并入同一张单（合并组可展开）；`chain` 下各自留单并以链条互指（上一单 / 下一单可展开）。
- **走法校验**：提交收口时实际走法必须与当日策略说明一致，否则服务端以「走法不符」拦下。
- **待复核**：处置单结案后再涌进同指纹新告警，旧单（及其成员告警）回到「待复核」，旧结案不再充当完成。
- **台面横排指标**：今日策略名、待认领数量、处置中数量、待复核数量、已结案数量。

### 核对脚本（七段）

`tests/test_segments.py`：

1. 同指纹按所选规矩合并或串联（两种规矩各跑一遍）
2. 走法不符被服务端拦下，按策略走法才放行
3. 双人争抢只成一笔、另一笔记争抢失败；认领必须带操作员名
4. 空级别告警无法认领、无法进合并
5. 处置没收口时改策略说明失败；当天不许换规矩
6. 结案后同指纹新告警进台，处置单回到待复核（merge / chain 各一例）
7. 台面一眼认出策略名、待认领数量与争抢落败
